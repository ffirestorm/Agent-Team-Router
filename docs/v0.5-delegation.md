# ATR V0.5：原生子代理委派

V0.5 将开发配置调整为轻量、按需的原生委派建议。ATR 提供配置、预览和指引；实际任务分派由 Codex 主模型依据项目指引执行，ATR 不运行调度器，也不拦截模型调用。

## 开发配置

开发配置包含三个角色：

| 角色 | 默认模型 / 推理强度 | 用途 |
|---|---|---|
| `atr_simple_worker` | Luna / low | 边界清楚、风险低、可写的简单任务 |
| `atr_worker` | Terra / medium | 常规实现任务 |
| `atr_explorer` | Luna / low | 可选的只读探索 |

原有开发配置中的 `atr_reviewer` 被 `atr_simple_worker` 取代。其他配置档保持不变。安装迁移会移除 ATR 管理的开发配置 reviewer 定义，保留用户的其他角色定义和主模型选择。

应用开发配置时，ATR 会在 `AGENTS.md` 中写入明确的原生委派指引。这些指引是供主模型遵循的工作规则，不是外部自动调度或强制机制。规模很小、目标含糊、复杂或高风险的任务应留给用户当前选择的主模型；不应为了委派而委派。

轻量原生流程不默认启动 reviewer，也不追加独立验收/测试流水线、修复重试或自动升级。既有 `atr run` 受控执行器仍保留，只在用户明确要求该模式时使用。任务本身需要的普通检查仍可按任务要求执行。`balanced`、`quality` 和 `code-review` 等其他配置档仍可按需使用，尤其适用于用户明确要求的审查流程。

## 预览命令

```sh
atr delegate TASK [--complexity simple|medium|complex] [--risk low|normal|high] [--tiny]
```

该命令只预览建议，不创建子代理、不调用模型、通过轻量规则判断任务复杂度和风险，也不写入执行记录。它会核对建议路由对应的原生角色配置，其模型和推理强度是否符合预期配置。

`atr plan` 的输出包含 `native_delegation` 字段，用于说明原生委派建议。

## 启用和加载配置

首次安装或初始化时可指定开发配置：

```sh
python -m pip install /path/to/Agent-Team-Router
atr init --profile development
```

现有安装也可切换配置并检查变更：

```sh
atr profile use development
atr apply --dry-run
atr apply
```

应用配置后，需要使用可信项目并开启一个新会话，Codex 才会加载更新后的角色和项目指引。ATR 不会覆盖用户选择的主模型。

委派的叙述和进度说明不需要 hooks。原生记录默认关闭，ATR 不会自动开启。若用户显式启用记录，应遵循项目的记录设置。

## 委派工作约定

主模型准备委派时，应先说明将交给哪个角色、该角色配置的模型和任务。实际创建原生子代理后，应展示宿主返回的 ID 和启动状态；后续只转述实际观察到的进度与结果，不声称未运行的检查，也不把配置模型说成已由后端证明实际使用的模型。

尽量缩小委派上下文；宿主支持时避免传入完整历史。让子代理返回简洁摘要，不委派微小任务，不无故启动 reviewer，并避免多个子代理同时写同一文件。节省 token 并无保证：总 token 可能增加，配额也受模型、上下文和缓存影响。需要比较时，应使用匹配的任务与条件进行测量。

原生子代理的 UI 和状态控制取决于宿主能力；ATR 不保证提供自定义时间线。

`atr plan.initial_execution` 是既有隔离执行器的初始模型建议，不能解读为主模型被切换。原生分工查看 `native_delegation`；它核对已应用的角色/模型/强度，未应用或不匹配时留给主 Agent。规则是启发式，不证明任务难度或模型能力。

## 本版验证

本地 macOS / Python 3.12：224 项通过，2 项 Windows 专属测试跳过。源码包和 wheel 构建、全新虚拟环境安装验证通过，见 [v0.5-distribution-smoke.json](v0.5-distribution-smoke.json)。

真实 Codex 临时项目探针确认两个可写开发角色被配置发现、用户选择的主模型保留、未加入 Reviewer，且没有安装 hooks、记录仍为 off，见 [v0.5-delegation-probe.json](v0.5-delegation-probe.json)。探针仅使用 initialize/config-read，不发起推理；不把元数据发现当作真实子任务或节省额度证明。远程跨平台结果以对应提交的 GitHub Actions 为准。
