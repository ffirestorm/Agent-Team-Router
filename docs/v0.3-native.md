# V0.3：Codex 原生会话记录

目标：正常向 Codex 提需求；有分工时先看到“计划分配什么角色/模型做什么”，结束时看到对应执行记录。首次安装与信任后，不需要用户每个任务再输入 ATR 命令。

## 一次性启用

在目标项目中，从 V0.3 源码安装 ATR（尚未发布到 PyPI），并安装支持 hooks 的 Codex CLI：

```bash
python -m pip install /path/to/Agent-Team-Router
atr init --profile development
atr native install --dry-run
atr native install
```

已有 `.atr/config.toml` 时跳过 init。install 会同时应用当前 Profile、安装 Skill、补充 AGENTS.md 托管区块、复制标准库独立记录器、合并项目 hooks。它不会调用模型、写入全局配置或信任记录。

在 Codex 中信任该项目，审阅并信任项目 hooks：CLI 使用 `/hooks`；桌面端使用可用的 Review hooks 入口或 Settings > Hooks。然后开启新会话。主机必须允许项目 command hooks；管理员禁用、旧版本、远程执行方式或其他专用路径可能不支持。升级后定义变化需要重新审阅；记录器也应一并审查。[官方 hooks 文档](https://learn.chatgpt.com/docs/hooks)描述了事件、信任和客户端覆盖范围。

这是平台对执行本地脚本的信任要求。ATR 不绕过它，也不以“安装完成”声称记录已生效。

## 日常体验与准确性

正常输入工程需求即可。主 Agent 通过项目指令和 SessionStart/UserPromptSubmit 上下文获得流程与当前报告路径：

1. 有必要且宿主允许分工时，先说明角色、配置中的模型和任务。这是计划。
2. 使用 Codex 原生工具实际分配；原生 hooks 收集 Agent 启停、模型请求、请求结果和可用的 Token 字段。
3. 主 Agent 可内部调用固定 Python/独立 helper，为返回的 Agent ID 补充简短任务标签，用户不用输入记录命令。
4. 最终回复前，主 Agent 读取本轮报告，汇总观测到的角色、模型、任务和执行状态，并另列实际测试证据。

**过程说明和最终汇总由模型遵循指令完成，不能保证每次措辞或展示。** hooks 本身不注入任意聊天消息，也不控制 Codex 前端。若宿主禁止子 Agent，简单任务只由主 Agent 处理，报告也可以只含主 Agent。

配置模型、启动时模型、实际请求模型分别保留；实际模型列仅来自 Pre/PostModelRequest，是宿主报告值，不是服务端独立认证。标签和计划属于主 Agent 声明。请求 `completed` 和 Agent `stopped` 都不代表工程验收成功；原生观察模式没有独立验证器，验收显示 `not_observed`，最终测试结论由具体测试输出支持。

最终回复是在 Stop 之前写出的，最后一次请求的结果/用量可能在回复后补记。报告标注事件序号；收尾后查看磁盘报告可得到后续补充。缺失字段显示未知，缺失用量不会按零计费，费用保持 null。记录中无事件、请求不配对或缺少停止事件时给出覆盖不完整提示。

## 记录与诊断

```bash
atr native status
atr native sessions
atr native report --session SESSION_ID
atr native report --session SESSION_ID --turn TURN_ID --format json
```

这些是可选的排查命令，不是每次任务的操作要求。`status` 区分已安装与曾观测到事件，但不会声称已验证当前客户端信任状态。Session/turn ID 来自 hooks，不能凭空推断。

本地文件：

- `.atr/native/events.sqlite3`：允许字段的事件数据库，支持并发写入，不按相同内容去重（重试也可能完全相同）。
- `.atr/native/sessions/<session-hash>/summary.json`、`summary.md`：会话报告。
- 同目录下 `turns/<turn-hash>/summary.*`：本轮报告，按父子 Agent 关系聚合并隔离不同轮次。
- `.atr/native-install.json`：安装清单；`.codex/atr_native_hook.py`：项目绑定的独立记录器。

不读取私有会话数据库或 transcript，不上传数据，不保留完整用户输入、任务 message、工具输出或原始错误。任务 message 和错误只保留摘要哈希；显式简短任务标签、角色和模型会落盘，并做有限的常见密钥脱敏，**任务标签仍应避免敏感内容**。Session/turn/Agent ID、时间和用量是本地元数据。`.atr/` 已被本仓库 gitignore；使用其他项目时也应将其加入忽略列表。

数据库是事实来源，JSON/Markdown 是派生快照。hook 出错时退出 0 并输出空 JSON，错误类型写 stderr，不阻塞任务，不返回触发新一轮执行的 Stop 决策。导出失败不会撤销已写入的事件，CLI report 可重算。磁盘只读、Python 被删除或超时等情况可能导致事件缺失；这不是完整审计承诺。

## 修改、暂停、卸载与恢复

install 固定当前 Python、项目绝对路径和 launcher，不依赖当前 PATH 上另一个 atr。移除虚拟环境、移动项目或复制到其他系统前先卸载；在新位置重新安装。Windows 对含命令解释器特殊字符的安装路径明确拒绝，避免错误转义。绑定项目外的工作树不在 V0.3 采集范围内，需要在对应工作树单独初始化安装。

```bash
atr native uninstall --dry-run
atr native uninstall
atr rollback
atr recover
```

卸载只移除自有 hook 组、launcher、安装清单和原生会话指令，保留静态团队、通用 Skill 和历史记录。原有 hooks 的字节内容在无其他变化时原样还原。install/uninstall 使用现有事务备份，可回滚和故障恢复。已有 inline `[hooks]` 时要求先协调迁移，避免同一层双配置。

当前事务系统保守地管理整个 hooks.json；安装前的其他 hooks 会保留，但安装后人工修改托管文件会触发冲突。需新增自定义 hooks 时，先卸载、编辑、重新安装并重新审阅；不通过强制覆盖吞掉用户修改。普通 `atr apply` 保留已安装的会话指令。

可在 Codex hook 管理器中禁用记录器，或临时创建 `.atr/native/disabled` 标记；删除标记后恢复。禁用不会删除历史数据。

## 与 V0.2 的关系、验证范围

V0.2 的 `atr run --execute` 继续提供隔离执行、固定验证和受控升级，且禁用其内部原生 hooks，避免混淆记录。V0.3 的被动 hooks 不切换模型、不重试任务，也不会把一次错误自动归因为模型能力不足。复杂通信、自动调度和 WorkflowArena 评测后置。

自动测试覆盖合并、幂等、回滚、卸载、独立脚本、并发事件、会话/轮次隔离、缺失模型/用量、隐私字段和失败放行。`python examples/native_hooks_probe.py` 使用真实 Codex、临时项目和临时 CODEX_HOME，仅调用 initialize/hooks/list；确认 11 个 handler 被发现且保持 untrusted，不请求推理也不写 hook 信任。真实元数据结果见 [v0.3-native-probe.json](v0.3-native-probe.json)。回调协议测试使用合成事件，不冒充实际桌面任务。当前用户会话的真实回调需首次审阅信任后确认。
