# V0.4：记录可控、存储可控、状态可查

V0.4 实现 P0/P1 的记录管理、查询、任务草稿和持续工程验证。**原生执行记录默认关闭**：首次安装、V0.3 升级后没有显式设置时都不采集。安装不代表启用。当前仓库也保持关闭。

## 记录开关与级别

```bash
atr native install          # 安装配置，默认不采集；已明确启用的设置在重装时保留
atr native status
atr native on               # 仅用户明确需要时启用；默认 summary
atr native on --level detailed
atr native off
```

- `off`：hook 快速返回，不写事件、报告或诊断；不删除历史。安装的 hook 仍可能由 Codex 启动 Python，要完全避免进程启动可在 Codex Hooks 设置中禁用。
- `summary`：保留 Agent 生命周期、模型请求与结果、可用用量和显式任务标签；跳过委派工具事件及 message/error 摘要。报告文件仅在生命周期边界生成，减少派生文件重写。
- `detailed`：保留原 V0.3 允许字段的委派工具元数据、摘要哈希，及时更新报告。仍不保留完整对话、工具输出或原始错误。

缺少 `.atr/native/settings.json` 时是 off。`.atr/native/disabled` 是兼容旧记录器的最高优先级关闭标记；`on` 显式写设置并移除标记，`off` 同时写入标记。开关设置独立于静态托管哈希，切换不会造成 apply 冲突；install、apply、Skill 和任务草稿均不会偷偷启用。升级后的 hook 定义变化仍需在 Codex 审阅信任，ATR 不代写信任。

模式开关不影响 `atr run` 必需的受控执行记录。后者仅在明确执行任务时产生，用于验收、取消和追溯；本版清理范围是 `.atr/native/`，不删除 `.atr/runs/` 候选与证据。

## 健康与便捷查询

```bash
atr native health
atr native health --recent-minutes 30
atr native sessions
atr native report --latest
atr native report --latest --turn latest --format json
atr native report --session SESSION --agent AGENT_ID
atr native report --current
```

health 区分 `off`、`not_confirmed`、`stale`、`error` 和 `recent_events`，展示最近 hook 时间、近期观测类型、未观测类型、请求不配对等提示及本地存储大小。启用时最多保留一个 `last-error.json`，内容仅含错误类型、代码位置与时间；关闭后不更新它。后续成功回调可解除近期错误状态，历史错误仍可查看。未观测某类型也可能只是本次没用到；近期回调不等于已检查当前宿主的 hook 信任。

`--latest` 选最近有事件的会话家族，将子 Agent 请求归到父会话；不是“当前聊天”的同义词。`--current` 仅使用宿主环境 `CODEX_THREAD_ID`，缺失时报错，不猜测；有 hook 上下文时主 Agent 可直接用其中的 session ID。`--turn latest` 查询父会话最近已观测轮次。`--agent` 过滤 Agent 行和声明标签，报告的总事件数仍是所选会话/轮次总量。

关闭时仍可查询旧记录，但状态明确显示 off。摘要文件可能是历史快照；CLI/helper report 从数据库实时重算，收尾回复应使用实时查询。

## 历史清理

```bash
atr native cleanup --older-than-days 30          # 默认预览，不删除
atr native cleanup --keep-sessions 20
atr native cleanup --max-mib 100
atr native off
atr native cleanup --older-than-days 30 --execute
```

可组合条件：年龄和保留数量选择其并集，再为容量目标选择更老会话。数量按会话家族计数，父子 Agent 历史一起处理；不拆散关联记录。默认保护 5 分钟内活跃、缺失结束、模型请求未配对或仍有子 Agent 启动未停止的会话。确认陈旧不完整会话可删除时，可显式加 `--include-incomplete`；5 分钟近期保护仍保留。

清理执行要求 recording off，并使用项目锁、maintenance 标记与 SQLite 写锁；采集器进入数据库事务后再次检查停用/维护状态。预览列出会话、事件数、保护列表和估计释放空间。执行删除所选事件及其派生报告，再 VACUUM 回收数据库页。不会删除配置、安装备份或受控执行证据。

容量是尽力目标，保护会话、数据库基础页和设置文件可能让最终大小仍超过目标。估计量不含完整页/索引开销，执行后返回实际存储大小。清理是显式不可逆删除，不参与配置 rollback；不自动定时删除。磁盘/权限故障可能留下部分派生文件，执行报错后应检查结果再重试，不能当作清理成功。出现遗留 maintenance 标记时，确认没有清理进程后再移除。

## 自然语言需求转任务契约

模型可在对话内部调用草稿入口，不要求用户自己编写整份 JSON：

```bash
atr task templates
atr task draft "为缓存增加过期机制" --allow src/cache.py
```

描述、修改范围、baseline 和独立 verify 是不同信息。缺少后两者时返回 `ready: false` 和待补信息；指定输出时保存不可执行提案，`atr run` 不会将其当作有效契约。草稿生成不调用模型、不执行任何 argv，也不以自然语言自动编造验收。

完整 custom 示例：

```bash
atr task draft "为缓存增加过期机制" --id cache-expiry \
  --allow src/cache.py \
  --baseline-json '["{python}","-m","pytest","-q"]' \
  --verify-json '["{python}","{task_dir}/verify_cache.py"]' \
  --output .atr/tasks/cache-expiry/task.json
```

自定义 verifier 由工程负责人准备。可复用 pytest JSON 验收模板：

```bash
atr task draft "为缓存增加过期机制" --allow src/cache.py \
  --template pytest --acceptance-test acceptance/test_cache.py \
  --output .atr/tasks/cache-expiry/task.json
atr run .atr/tasks/cache-expiry/task.json --dry-run
```

pytest 模板要求验收测试已存在且位于模型允许修改范围之外，生成固定哈希清单及标准库 `verify.py`。默认 baseline 为 pytest 并忽略这些验收文件，避免尚未实现的验收挡住既有基线；可显式指定自己的 baseline。verify 中 pytest 0=passed，1=failed，其他退出码=error；验收文件哈希变化是 error，不触发模型升级。模板仅适用于已有 pytest 的 Python 工程，不自动安装依赖。`--output` 缺失时只预览，不声称验证器已生成。

任务契约和 verifier 一起通过事务写入新目录，可 rollback；已有输出拒绝覆盖。所有工程验收/路径仍需结合实际需求检查。与 V0.2 一样，只有 `run --execute` 才会调用模型，升级需明确启用；不自动合入补丁。

## 按模型统计与真实自测

```bash
atr runs report --by-model
```

按每次尝试的模型汇总涉及任务数、尝试数、通过次数、失败分类、升级尝试/通过次数、已知 Token、缺失用量、耗时和费用。重复修正计多次尝试、同一任务对同一模型只计一次任务；缺失费用保持 null。缓存输入是 input 子集。各模型任务难度不匹配，这些统计不作为能力排名或升级效果的因果结论。

本版本用真正要接入 CLI 的 [model-metrics.json](../evals/dogfood/model-metrics.json) 完成受控工程自测，由 `atr task draft` 生成契约；独立验证见 [verify_model_metrics.py](../evals/dogfood/verify_model_metrics.py)。Terra 在 180 秒预算处超时，执行器按规则停止，没有升级；候选仅改了统计模块及测试。之后独立验收通过，候选完整回归 194 项通过、1 项跳过，经审查后集成。原执行记录保持 budget_exceeded，独立验收不回写原状态。摘要见 [v0.4-dogfood.json](v0.4-dogfood.json)。

这验证了真实超时不会误触发升级，以及候选可以独立验收；不宣称真实 Terra→Sol 挽救已验证。自然发生的合格质量失败、真实子 Agent 完整 hook 链路仍需后续验证。当前仓库原生记录保持关闭，不为自测强制开启；协议回调与管理测试只在隔离临时项目中显式启用。
