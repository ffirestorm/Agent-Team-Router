# V0.2 开发版：受控模型升级与真实工程自测

状态：`0.2.0.dev0` 开发源码，尚未创建 V0.2 发布标签或 Release。跨平台构建状态见 [GitHub Actions](https://github.com/ffirestorm/Agent-Team-Router/actions/workflows/ci.yml)。V0.1.0 标签与已发布附件保持原状。本轮不接入 WorkflowArena。

## 可以实际运行的功能

- `plan` 展示原有团队建议及 `initial_execution` 单任务初始策略。
- `run TASK.json` 默认只预览；仅加 `--execute` 才调用真实模型。
- 使用仓库当前内容快照，包含已跟踪及未忽略的用户未提交修改；不改原始工作目录、不创建 Git 提交。
- 运行既有测试基线，确认新任务未完成，再执行模型。验收通过后还需通过基线回归。
- 固定 JSON 验证器、失败复现检查、同模型一次修正、一次升级、最多三次 Codex 调用。
- 运行记录、原始本地事件、Token、耗时、候选补丁；取消和保守的中断记录恢复。

## 三档模型策略

默认简单任务使用 `fast/low`，中等任务 `balanced/medium`，复杂任务 `reasoning/high`。实际模型由已有 `[models]` 映射决定；默认示例对应 Luna、Terra、Sol。初始难度仍基于已有关键词启发式，不是经过训练的分类器。`--complexity simple|medium|complex` 可以手动覆写。

在 `.atr/config.toml` 中添加可选设置：

```toml
[routing.simple]
tier = "fast"
effort = "low"
[routing.medium]
tier = "balanced"
effort = "medium"
[routing.complex]
tier = "reasoning"
effort = "high"

[execution]
allow_escalation = false
same_model_retries = 1
max_attempts = 3
timeout = 600
attempt_timeout = 180
verifier_timeout = 60
escalation_tier = "reasoning"
escalation_effort = "high"
# max_tokens = 50000  # 调用结束后阻止下一次调用，不是当前调用硬上限
```

每档还可指定已映射的 `model`。所有规则（包括当前未使用的档位）都会验证。自动升级缺省关闭，可通过配置或每次执行的 `--allow-escalation` 明确启用；目标必须是配置中不同且更高档的模型，没有合格目标时停止。配置档位不保证相对成功率或价格。

运行时初始选择以 routing 为准，不隐式套用静态 Profile 的角色模型覆写。Profile 用于原生团队配置并保留 code-review 禁止修改型执行的约束；节约型执行应显式设置 routing 与 execution 预算。

## 任务从哪里来

直接使用 ATR 自己的开发任务。首个任务是 [initial-policy.json](../evals/dogfood/initial-policy.json)，要求实现真正被 CLI 使用的三档初始策略与测试。任务定义五个必需字段：

```json
{
  "id": "my-feature",
  "description": "明确的工程需求及验收要求",
  "allowed_paths": ["src/package/feature.py", "tests/test_feature.py"],
  "baseline": ["{python}", "-m", "pytest", "-q"],
  "verify": ["{python}", "{task_dir}/verify_feature.py"]
}
```

`baseline` 是必须已经通过的测试，不是尚未实现的新功能测试。`verify` 是预先批准的独立验收脚本，应保存在模型可写范围之外。参数按 argv 执行，不通过 shell；`{python}` 指当前 Python，`{task_dir}` 指原始任务 JSON 所在目录。

验证器 stdout 必须是单个 JSON 对象：`status=passed` 配退出码 0，`status=failed` 配退出码 1，其他验证故障使用 `status=error`。均需非空 reason；failed 还必须给出稳定的 failure_id。预览时记录任务文件和 argv 中直接引用的外部验证文件哈希，执行前、每次调用前及完成时重新检查，变化后要求重新预览；这不是对全部依赖的容器级封存。只有执行器完成、基线健康、验收失败可复现且验证器没有改文件时，才产生升级候选。权限、额度、网络、验证器错误、未知原因、取消和超时均不触发模型升级。初版基础设施错误直接停止，没有自动网络重试层；Codex 自身的内部重连受整个调用墙钟时间限制。

公开的工程验收允许将失败反馈交给下一次修正。未来外部基准的隐藏验证必须另行隔离，不能沿用公开反馈协议泄露隐藏评测信息。

初版若新功能验收通过但既有测试回归失败，会保守停在 needs_attention，不将通用测试命令的非零退出码直接归因为模型能力问题。需要自动修正的失败应由固定 JSON 验证器提供明确、可复现的任务证据。

## 使用命令

```bash
python -m pip install -e '.[dev]'
atr init --profile development  # 若已初始化则用 atr profile use development
atr plan "实现执行记录查询" --complexity medium
atr run /path/to/task.json --dry-run
atr run /path/to/task.json --execute --allow-escalation
# 可显式覆盖初始模型和强度；ID 必须在本地模型映射中
atr run /path/to/task.json --model gpt-6.1-terra --effort medium --execute
atr runs list
atr runs show RUN_ID
atr runs report
atr runs cancel RUN_ID
atr runs recover RUN_ID
```

当前目标必须是 Git 仓库根目录；code-review Profile 禁止修改型执行。快照不复制 `.git/.atr/.venv/node_modules/.codex/.agents/dist`，保留可见的项目 AGENTS.md；拒绝符号链接及超过 50 MiB 的源快照。依赖必须事先安装，Python 验证使用当前解释器和候选 `src`。

记录在 `.atr/runs/RUN_ID/record.json`，候选目录为 `workspace/`，差异为 `candidate.patch`。不自动合并；审查候选并确认原始文件未变化后再集成。当前补丁导出适用于 UTF-8 文本，不支持二进制修改或文件权限变更。

## 预算、权限和恢复边界

运行次数、调用超时、总墙钟时间可控制；Token 只能在宿主回报用量后累计，超出时禁止后续调用。用量未知且设置了 Token 门槛时，也停止后续调用。不支持无法兑现的费用硬限制。

Codex 使用原生 workspace-write sandbox、never 审批和无多 Agent 的独立 exec。保留本机认证存储，不改全局配置；只转发提供者的必要传输字段，拒绝 URL 内认证信息和自定义认证 header。忽略无关用户配置，避免把 hooks/plugins 带入隔离任务。此功能要求本机 CLI 支持 `--json/--ephemeral/--ignore-user-config/--skip-git-repo-check`。

允许修改路径是候选审计条件，不是操作系统级逐文件权限边界。模型可写的是整个候选目录，原生 sandbox 限制模型工具执行；基线和验证命令以用户权限运行，需使用自己批准的命令。该版本不承诺隔离恶意验证脚本或恶意候选代码，不能作为运行不可信代码的安全容器。

取消由控制器检测取消标记后终止进程树。控制器被强制杀死时，先检查记录的 PID 和残留进程，确认无执行后再处理遗留 `.atr/lock`；`runs recover` 遇到仍存在的记录进程会拒绝恢复，永不自动重放模型调用。当前不是自动断点续跑系统。

## 本次真实工程结果

2026-11-10，使用 ATR 执行自身的三档策略任务：

1. 首次配置未保留本机 HTTP 传输选择，出现重连，单次超时后停止，没有升级。
2. 修正过程中一次提供者参数编码错误被 CLI 拒绝；记录保留为启动失败，没有发起模型推理，也没有升级。
3. 修正并完成隔离原生验证后，Terra 一次完成 `task_policy.py` 和对应测试；固定验收和完整回归通过。代码经检查后集成，未人为制造失败或调用 Sol。

成功记录：`34a63baa9ab847fcb4d235d72066382c`。耗时约 187.4 秒（含基线、执行、验收和回归）；输入 175412 Token，其中缓存输入 158592，输出 2971。缓存输入是输入总量的子集，不能重复相加。费用和 Plus 额度消耗均不可观测，为 null。前两次失败的完整用量不可观测，不补成零。

三次流程尝试全部保留，当前本地报告为 3 次开始、1 次成功、0 次升级。不能据此推断 Terra 的成功率或升级策略的收益。受控升级的正反路径目前由模拟执行器覆盖；真实 Terra→Sol 挽救效果仍待后续工程任务自然出现合格失败时验证。摘要见 [v0.2-dogfood.json](v0.2-dogfood.json)。

统计中基线失败也计入已开始任务分母；任务在调用模型前已经满足时单列，不记为模型首次成功。已知 Token 小计与缺失尝试数分别展示，不把缺失记录当作零用量。一般 run report 用于工程可追溯，不等价于控制了任务难度与环境的模型评测。
